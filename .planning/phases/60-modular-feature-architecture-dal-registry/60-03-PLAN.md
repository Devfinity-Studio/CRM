# Plan 60-03: CMS & Content Configuration Layer, Verification & Documentation

## Objective
Separate static brand assets from mutable content/CMS blocks, verify end-to-end type safety, ensure zero regressions across production routes, and document the baseline architecture for future remote feature flags (ConfigCat/Unleash).

## Proposed Changes

### 1. CMS & Content Configuration Layer
- Create `src/config/brand.ts`:
  - Static brand identity: `BRAND_NAME`, `BRAND_TAGLINE`, `LOGO_ASSETS` (light/dark/favicon), `SOCIAL_LINKS`, `SUPPORT_EMAIL`.
- Create `src/config/content.ts`:
  - Mutable CMS blocks: Landing page hero copy, feature highlights, onboarding tips, promotional announcements, and dashboard banner messages.
- Refactor landing page (`src/app/page.tsx`) and layout elements to consume content from `src/config/content.ts` and `src/config/brand.ts`.

### 2. Theme & Accessibility Audit
- Ensure all views respect system dark/light mode (`prefers-color-scheme`) and meet contrast requirements.

### 3. Verification & Build Integrity
- Run TypeScript strict typecheck: `pnpm tsc --noEmit`.
- Run all Vitest suites: `pnpm test`.
- Run Next.js 15 production build: `pnpm build`.

### 4. Architecture Documentation
- Create `.planning/phases/60-modular-feature-architecture-dal-registry/60-ARCHITECTURE.md`:
  - Detailed summary of newly established boundaries.
  - Map of DAL operations and feature modules.
  - Step-by-step roadmap to integrate remote feature flags (ConfigCat/Unleash/PostHog) using the new registry.
