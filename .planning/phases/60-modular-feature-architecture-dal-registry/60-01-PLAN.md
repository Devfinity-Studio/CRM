# Plan 60-01: Strict Tenant Isolation & Server Data Access Layer (DAL)

## Objective
Establish a centralized, server-side Data Access Layer (DAL) that guarantees strict tenant isolation. All data access operations will enforce authenticated session tenant boundaries and role-based permissions (`OWNER`, `ADMIN`, `MEMBER`, `VIEWER`), eliminating direct un-scoped queries.

## Proposed Changes

### 1. Data Access Layer Foundation (`src/server/dal/`)
- `src/server/dal/tenancy.ts`:
  - `resolveTenantSession(ctx)`: Resolves tenant ID from session / validated membership.
  - `assertTenantRole(ctx, allowedRoles: OrgRole[])`: Throws `TRPCError({ code: "FORBIDDEN" })` if user lacks required role.
  - `assertTenantAdmin(ctx)`: Convenience guard for administrative tenant actions.
- `src/server/dal/crm.ts`:
  - Encapsulate scoped queries for `companies`, `contacts`, and `crmLeads`.
  - Transparent handling of PII encryption / decryption.
- `src/server/dal/deals.ts`:
  - Encapsulate scoped queries for `deals`, `pipelines`, `pipelineStages`, and `dealProducts`.
- `src/server/dal/billing.ts`:
  - Encapsulate scoped queries for `invoices`, `quotes`, `products`, `payments`, and `clientSubscriptions`.
- `src/server/dal/automations.ts`:
  - Encapsulate scoped queries for `automationRules` and `automationLogs`.
- `src/server/dal/members.ts`:
  - Encapsulate scoped queries for `organizationMembers` and tenant staff governance.

### 2. Domain Router Integration
- Refactor procedures in `src/server/api/routers/` to delegate data retrieval and mutations to the DAL functions, ensuring consistent multi-tenant boundary checks.

### 3. Automated Tests (`src/server/dal/__tests__/dal-isolation.test.ts`)
- Unit test suite verifying that cross-tenant access is rejected when requesting resources belonging to another organization.
- Test role assertions (`assertTenantAdmin` passes for OWNER/ADMIN and rejects MEMBER/VIEWER).
