# Plan 59-01: Global Staff & User Governance Backend Engine

## Objective
Establish database-backed user governance capabilities: account suspension via `isActive` flag, authentication enforcement, self-protection guards, administrative password reset with `bcrypt`, instant session revocation, staff user creation, and comprehensive audit logging.

## Proposed Changes

### 1. Schema Updates (`src/server/db/schema.ts`)
- Add `isActive: d.boolean().default(true).notNull()` to `users` table.

### 2. NextAuth Hardening (`src/server/auth.ts`)
- Update `CredentialsProvider`'s `authorize` method to reject login if `existingUser.isActive === false`.

### 3. Superadmin Router (`src/server/api/routers/superadmin.ts`)
- Implement `getGlobalUsers`:
  - Input: `search?: string`, `systemRole?: "SUPER_ADMIN" | "USER" | "ALL"`, `status?: "ACTIVE" | "SUSPENDED" | "ALL"`, `limit?: number`, `offset?: number`.
  - Joins with `organizationMembers` and `organizations` to populate user's organizational context.
  - Strips `passwordHash`.
- Implement `updateUserSystemRole`:
  - Input: `userId: string`, `systemRole: "SUPER_ADMIN" | "USER"`.
  - Self-demotion guard: Throws `BAD_REQUEST` if `userId === ctx.session.user.id && systemRole !== "SUPER_ADMIN"`.
  - Logs `UPDATE_USER_ROLE`.
- Implement `toggleUserActiveStatus`:
  - Input: `userId: string`, `isActive: boolean`.
  - Self-suspension guard: Throws `BAD_REQUEST` if `userId === ctx.session.user.id && !isActive`.
  - Automatically revokes user sessions when `isActive` is set to `false`.
  - Logs `ACTIVATE_USER` or `SUSPEND_USER`.
- Implement `adminResetUserPassword`:
  - Input: `userId: string`, `newPassword: string` (min 8 chars).
  - Hashes password using `bcryptjs.hash(newPassword, 10)`.
  - Automatically revokes active user sessions so re-login is required.
  - Logs `RESET_USER_PASSWORD`.
- Implement `revokeUserSessions`:
  - Input: `userId: string`.
  - Deletes all records from `sessions` where `userId === input.userId`.
  - Logs `REVOKE_USER_SESSIONS`.
- Implement `createStaffUser`:
  - Input: `name: string`, `email: string`, `password: string`, `systemRole: "SUPER_ADMIN" | "USER"`.
  - Verifies email uniqueness, hashes password, inserts into `users`.
  - Logs `CREATE_STAFF_USER`.

### 4. Automated Tests (`src/server/api/__tests__/superadmin-users.test.ts`)
- Verify `getGlobalUsers` query with filters.
- Verify role elevation and prevention of self-demotion.
- Verify suspension and prevention of self-suspension.
- Verify password reset and session revocation.
- Verify staff user creation with hashed passwords.
