# Phase 56.1 - Plan 01 Summary: PII Encryption Engine & Public Ingestion Endpoint Hardening

**Completed at:** 2026-11-06
**Status:** Completed

## Implementation Summary
1. **PII Envelope Encryption Engine (`src/server/security/encryption.ts`)**:
   - Implemented AES-256-GCM envelope encryption format `enc:v1:<iv>:<auth_tag>:<ciphertext>`.
   - 96-bit random IV per value, 128-bit authentication tag for integrity verification.
   - SHA-256 deterministic key derivation from `ENCRYPTION_SECRET` / `AUTH_SECRET`.
   - Graceful backward-compatible fallback for legacy unencrypted database rows.
   - Fail-safe handling for corrupted ciphertext or mismatched authentication tags returning `[RESTRICTED_PII]`.
   - Implemented privacy masking helpers:
     - `maskAadhaar(val)` -> `XXXX-XXXX-1234`
     - `maskPan(val)` -> `XXXXX1234X`
     - `maskPassport(val)` -> `AXXXX123`

2. **Database Schema Update (`src/server/db/schema.ts`)**:
   - Updated `pan`, `aadhaar`, `passport` columns on `contacts` and `businessPan` on `companies` to `d.text()` to support envelope ciphertext lengths.

3. **CRM Router Integration (`src/server/api/routers/crm.ts`)**:
   - `createContact`: Transparently encrypts `pan`, `aadhaar`, `passport` prior to DB insertion.
   - `getContacts` and `getPOCsByCompanyId`: Decrypts PII fields and generates masked variants (`panMasked`, `aadhaarMasked`, `passportMasked`) for privacy-preserving client views.
   - `createCompany`: Encrypts `businessPan` on insertion.
   - `getCompanies`, `getCompanyById`, `getCompanyByName`: Decrypts `businessPan` and attaches `businessPanMasked`.

4. **Public Ingestion Endpoint Hardening**:
   - `/api/leads` (`src/app/api/leads/route.ts`):
     - Added Zod payload validation.
     - Added SHA-256 API key authentication (`Authorization: Bearer <key>` or `x-api-key: <key>`).
     - Verified organization existence and `isActive` status.
   - `/api/webhooks/ads` (`src/app/api/webhooks/ads/route.ts`):
     - Added secret header verification (`x-ad-secret` vs `AD_WEBHOOK_SECRET`).
     - Fail closed in production if secret is missing or mismatched.
     - Added Zod payload validation.
   - `public.submitQuoteRequest` (`src/server/api/routers/public.ts`):
     - Enforced `quantity >= 1` in Zod schema.
     - Verified organization existence and active status.
     - Fetched authentic product records from DB by `productId` to calculate `totalAmount` server-side, blocking client-side price fabrication.

5. **Unit Tests (`src/server/security/__tests__/encryption.test.ts`)**:
   - 11 unit tests covering encryption format, IV randomness, idempotence, decryption fidelity, legacy fallback, tamper detection, and masking functions.
   - 100% passing across 19 suites / 78 tests.
