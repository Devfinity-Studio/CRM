# Plan 56.1-01: PII Encryption Engine (AES-256-GCM) & Public Ingestion Endpoint Hardening

**Phase:** Phase 56.1 (Security Hardening & PII Encryption)
**Task:** 56.1-01
**Dependencies:** Phase 56
**Target Files:**

- `src/server/db/schema.ts`

- `src/app/api/webhooks/ads/route.ts`

- `src/server/security/__tests__/encryption.test.ts`

## Goals
1. **PII Envelope Encryption Utility (`src/server/security/encryption.ts`)**:
   - Implement `encryptPII(plaintext: string): string` using Node.js `crypto` with `aes-256-gcm`, generating unique 12-byte IV and 16-byte authentication tag per encryption.
   - Format: `enc:v1:<iv_hex>:<auth_tag_hex>:<ciphertext_hex>`.
   - Implement `decryptPII(ciphertext: string): string` with fallback handling for legacy plaintext values and verification of authentication tags.
   - Implement masking functions: `maskAadhaar(val)`, `maskPan(val)`, `maskPassport(val)`.
   - Key derivation using `process.env.ENCRYPTION_SECRET || process.env.AUTH_SECRET`.
2. **Schema Update (`src/server/db/schema.ts`)**:
   - Verify/update `pan`, `aadhaar`, `passport` columns in `contacts` table to `d.text()` or `d.varchar({ length: 255 })` to safely store serialized ciphertext.
3. **CRM Integration (`src/server/api/routers/crm.ts`)**:
   - In `createContact` and `updateContact`: Transparently encrypt `pan`, `aadhaar`, `passport` before database insertion.
   - In `getContacts`, `getContact`, and `getPOCsByCompanyId`: Return decrypted values for detail views and masked values (`aadhaarMasked`, `panMasked`, `passportMasked`) for tables/cards.
4. **Public Ingestion Hardening**:
   - In `/api/leads`:
     - Validate input payload using Zod.
     - Validate that `organizationId` exists and is active.
     - Require authentication via `Authorization: Bearer <token>` or `x-api-key: <key>`.
   - In `/api/webhooks/ads`:
     - Require matching `x-ad-secret` header against `process.env.AD_WEBHOOK_SECRET` (or fail closed in production).
   - In `src/server/api/routers/public.ts` (`submitQuoteRequest`):
     - Enforce `quantity >= 1` in Zod schema.
     - Fetch actual products from `ctx.db` by `productId` to retrieve the authentic unit price, preventing clients from submitting fabricated or negative prices.
5. **Testing**:
   - Write unit tests in `src/server/security/__tests__/encryption.test.ts` verifying encryption, decryption, tampering detection, and masking.
   - Verify test suite passes (`pnpm test`).
