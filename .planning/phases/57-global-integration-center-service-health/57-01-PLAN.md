## Goals
1. **Integration Health Diagnostic Service (`src/server/api/services/integrations-health.ts`)**:
   - `checkDodoHealth()`: Verifies API key, sends lightweight ping/list request, captures roundtrip latency (ms), and checks webhook secret presence.
   - `checkSvixHealth()`: Tests Svix API token via `svix.application.list({ limit: 1 })`, captures roundtrip latency (ms).
   - `checkStorageHealth()`: Tests Neon S3 storage via `HeadBucketCommand` / `ListObjectsV2Command` on `env.S3_BUCKET_NAME`, captures latency (ms).
   - `checkEmailHealth()`: Inspects configured email provider (Resend/SMTP/Mock), validates credentials, and measures connection latency.
   - `getAllIntegrationsHealth()`: Aggregates health across all 4 services concurrently with timeout handling.
2. **Super Admin Router Procedures (`src/server/api/routers/superadmin.ts`)**:
   - `getIntegrationsHealth`: Returns aggregated status, latency, environment, and error details for all 4 services.
   - `testDodoConnection`: Explicit on-demand diagnostic test for Dodo Payments.
   - `testSvixConnection`: Explicit on-demand diagnostic test for Svix Webhooks.
   - `testStorageConnection`: Explicit on-demand diagnostic test for Neon Object Storage.
   - `testEmailConnection`: Explicit on-demand diagnostic test for Email Delivery.
   - `getSvixApplications`: Lists tenant apps registered in Svix.
   - `dispatchSvixTestWebhook`: Dispatches a test event (`test.ping`) to verify outbound pipeline health.
   - `getPlatformStorageStats`: Returns platform-wide object count estimates and storage bucket health.
3. **Automated Vitest Test Suite (`src/server/api/__tests__/integrations-health.test.ts`)**:
   - Unit tests covering each diagnostic check, mocking successful and failing responses, validating latency calculation and proper error surfacing.

## Verification
